# sitewatch

监控网页变化的工具

开始是为了盯商品降价和公告更新，后来发现直接抓数据接口更省事。

## 能抓什么

- 普通网页（HTML）
- 数据接口（JSON）
- RSS / Atom
- 图片、PDF（只能判断变没变，看不到内容）

抓不到淘宝、微博这种整页靠 JS 画的。拿回来只有一个空壳，得去找它背后的接口。

## 怎么跑
要先安装依赖
```bash
py -3.13 -m pip install -r requirements.txt
```

然后双击 `启动.bat`，弹一个窗口出来。

加站点、删站点、看历史变化可以直接在窗口里点，不需要碰命令行。



## 加站点时


- **抓普通网页** → 填「选择器」，比如 `ul.t li`，只抓页面上这一块
- **抓数据接口** → 填「字段名」，比如 `code,title,bvid`，只留这几个字段

两栏都空着也能用，就是会连导航栏和页脚一起抓进来，之后天天报"有变化"。

不确定填哪个，就先留空加进去，看看抓到了什么，再回来改。

## 邮件通知

窗口右上角「设置」，填发件邮箱和授权码。

**授权码不是邮箱密码。** QQ 邮箱在「设置 → 账户 → 开启 POP3/SMTP 服务」里生成，16 位。



## 定时查询

目前只能靠 Windows 任务计划程序，设置时间才能自动运行


## 命令行也还能用

```bash
py -3.13 core.py add <名字> <网址> [--selector CSS] [--json-keys a,b]
py -3.13 core.py list
py -3.13 core.py check
py -3.13 core.py history <名字>
py -3.13 core.py preview <网址>
```

`preview` 是我用得最多的：加站点之前先跑一下，看它到底抓到了什么，不读库也不写库。

## 目前已知的不足

**抓不到 JS 渲染的页面。** 。

**通知不节流。** 榜单类站点半小时能换一半，任务计划如果半小时一次的话，一天发 48 封邮件。

**抓取失败看不见。** 定时任务在后台跑，目前出错只往控制台打一行提示，就可能出现某个站点挂了三天却没有受到任何短信，你唯一的察觉会是认为它好像一直没动静。

**快照只增不删，而且没索引。**  表现在一百来条，查什么都是瞬时的；一年后几万条。。


**只能本机跑。** 数据在本地保存，换台机器就没了，也没法多个人一起看。

## 数据在哪

`~/.sitewatch.db`，SQLite，两张表：

- `sites` — 监控项，以及每个站点上次抓到的内容
- `snapshots` — 每次变化存一条

想直接看原始数据，用 DB Browser for SQLite 打开这个文件就行。

## 目录

```
app.py        开窗口（pywebview）
web.py        FastAPI，页面和表单
core.py       命令行入口
fetcher.py    抓取，按内容类型分流解析
monitor.py    和上次的内容比对
db.py         SQLite 读写
notify.py     发邮件
changes.py    算两次快照之间差了什么
templates/    页面模板
static/       公共样式
```
